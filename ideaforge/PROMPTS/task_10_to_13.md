# task_10_claude_code_service.md
# INJECT WITH: MASTER.md + STACK.md + BUSINESS_LOGIC.md (Stage 4 Rules) + CONVENTIONS.md

Implement Claude Code CLI subprocess orchestration.

Files to create:
  backend/app/services/claude_code_service.py
    - ClaudeCodeSession class:
        __init__(project_id, project_path, context_files)
        start() → launches subprocess, writes context files to project_path
        inject(prompt: str) → writes to stdin
        read_output(timeout: int) → reads stdout until completion signal
        stop() → terminate subprocess, cleanup
        is_alive() → bool

    - run_task_via_claude_code(task, project, context) → dict
        1. Write all context files to /tmp/projects/{id}/
        2. Start ClaudeCodeSession
        3. Inject MASTER_PROMPT first
        4. Inject task prompt
        5. Read output (parse JSON files array)
        6. Return { files: [{path, content}] }

    - Completion detection:
        Watch stdout for JSON output containing "files" array
        Timeout: 300 seconds per task
        On timeout: treat as error, trigger handle_error

    - Context file injection:
        Write MASTER.md to project root before starting
        Write task-specific files per FILE_INJECTION_GUIDE.md
        Claude Code reads them naturally from project directory

Implementation notes:
  - Use asyncio.subprocess for non-blocking
  - Buffer stdout, parse complete JSON when detected
  - stderr: log all to execution_logs (event: claude_code_output)
  - CLAUDE_CODE_PATH from settings (default: claude)

Done when:
  - ClaudeCodeSession starts Claude Code in project directory
  - Prompt injected via stdin, output read from stdout
  - Timeout handled gracefully (error state, not hang)
  - Files parsed from Claude Code JSON output correctly

# task_13_deploy_integration.md
# INJECT WITH: MASTER.md + STACK.md + SCHEMA.md (deployments+user_integrations) + API_SPEC.md (STAGE 6) + BUSINESS_LOGIC.md (Stage 6 Rules) + CONVENTIONS.md

Implement Vercel + Railway deploy via their APIs.

Files to create:
  backend/app/services/deploy_service.py
    - deploy_frontend_vercel(project, repo_url, vercel_token) → dict
        1. POST https://api.vercel.com/v10/projects (link to GitHub repo)
        2. POST env vars (all NEXT_PUBLIC_* from project)
        3. POST https://api.vercel.com/v13/deployments (trigger)
        4. Return { deploy_id, status_url }
    
    - deploy_backend_railway(project, repo_url, railway_token) → dict
        1. GraphQL: projectCreate
        2. GraphQL: serviceCreate + link GitHub repo
        3. Set root directory to backend/
        4. Inject all backend env vars
        5. Trigger deploy
        6. Return { deploy_id, status_url }
    
    - poll_deploy_status(platform, deploy_id, token) → str
        Poll until: success | failed | timeout (5 min)
        Returns final status
    
    - health_check(frontend_url, backend_url) → dict
        GET {backend_url}/health → 200?
        GET {backend_url}/api/v1/auth/me → 401? (expected, means alive)
        GET {frontend_url} → 200?
        Returns { frontend: bool, backend: bool, db: bool, auth: bool }
    
    - handle_build_failure(platform, error_log, project, token) → bool
        Classify build error (missing env var, wrong start command, etc.)
        Attempt auto-fix via platform API
        Return True if fixed + retriggered, False if needs user

  backend/app/routers/deploy.py
    - All routes from API_SPEC.md STAGE 6 section
    - Broadcast deploy progress via WebSocket (reuse websocket_manager)

Done when:
  - POST /frontend triggers Vercel deploy with env vars injected
  - POST /backend triggers Railway deploy with env vars injected
  - GET /status returns live build status from both platforms
  - GET /health pings all 4 services, returns results
  - State advances to DEPLOYED on successful health check
